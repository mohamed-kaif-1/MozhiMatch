# Phase deliverables

Phases describe dependencies and ownership, not a requirement to serialise all work. A frontend shell can proceed during the core experiment, but inference-dependent product claims wait for the gate.

| Phase | Name | Deliverable | Primary task references |
|---|---|---|---|
| 00 | Requirements verification and initialization | S01 entry/brief, Git, Node and dependency candidate | K01–K02 / A01 |
| 01 | Critical feasibility proof | Rules, exact evidence and one live model/baseline gate | K04–K11 / A02 |
| 02 | Contracts and environment | Canonical schemas and reducer action contract | K03,K12 / A12 |
| 03 | Design system and shell | Tokens/fonts and one semantic screen | A03–A04 |
| 04 | Core/server foundation | Bounded API, access and health | K13,K15 |
| 05 | AI integration and evaluation | Adapter, structured output and measured comparison | K14 plus evaluation blocks |
| 06 | Core frontend workflow | Pair editor, queue, evidence and decision | A05–A07,A10–A17 |
| 07 | Tamil and English | Local messages/fonts/lang and no data loss on switch | A09 and locale hardening |
| 08 | End-to-end integration | IC2–IC4 and stale-request invariants | Joint checkpoints |
| 09 | Functional and security testing | Pure, route and workflow regressions | Both owner lanes |
| 10 | Responsive and accessible polish | Five widths, keyboard and reader observations | Aasim or solo Kaif |
| 11 | Deployment verification | Early shell, exact origins and release smoke | Kaif deploy, Aasim check |
| 12 | Demo and submission | Evidence, pitch, honest recovery and success confirmation | Kaif accountable |

Each phase completion names changed files, actual commands/results, remaining blockers and the next prerequisite. The final phase does not imply the event dashboard accepted an entry. Submission success must be observed. The user supplies account-specific secrets and any event clarification; routine local work continues independently where those are unnecessary.
