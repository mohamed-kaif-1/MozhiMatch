# Browser test plan

Playwright starts the local production-like server or connects to an explicitly configured baseURL. Intercept only the provider-backed analyze response in automated workflows, using the delivered response fixture. Tests must traverse the real / page, actual form controls and reducer. A separate live smoke is run by the operator after deployment.

Test load sample, compare, select a flagged field, inspect English/Tamil evidence, choose Fix, switch locale, copy issues and reset. Then test provider unavailable, invalid evidence, source edit during pending request and clipboard rejection fallback. Use five viewport projects or a compact loop for 360, 390, 768, 1024 and 1440 widths, in both locales. Assert scrollWidth≤innerWidth and visible focus/labels, with a human reading long Tamil labels.

Use accessible roles and labels in selectors, not positional CSS. Keyboard tests Tab through the page and activate source selection/actions. Check focus restoration after reset dialog. Reduced-motion preference is tested once. State tests must inspect text and interaction, not just compare screenshots.

Manual NVDA/Windows or another available screen-reader check remains necessary. The Linux environment does not establish laptop screen-reader behaviour. Record browser/version, locale and any skipped step. Do not call a blocked browser installation a passing E2E suite.
